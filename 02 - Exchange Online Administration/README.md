# Exchange Online Administration

## Overview

This section covers the core **Microsoft 365 administration** tasks I completed while supporting users and cloud services. I created and licensed a new **Microsoft 365 user account**, assigned the **Helpdesk Administrator** role using the principle of least privilege, and reviewed **Microsoft 365 Service Health** to identify and escalate potential service issues. These tasks demonstrate practical account provisioning, administrative access management, and service monitoring skills commonly used within an **IT Support** environment.

---

# Task 1 - Create a Microsoft 365 User Account

## Objective

Create a new **Microsoft 365** user account and assign a **Microsoft 365 Business Premium** licence to provide access to organisational resources, including **Exchange Online**, **Outlook**, **Microsoft Teams**, and other Microsoft 365 services.

---

## Implementation

I created a new **Microsoft 365** user account through the **Microsoft 365 Admin Center** by entering the user's basic account information, including their **first name**, **last name**, **display name**, and **username**.

After creating the account, I assigned a **Microsoft 365 Business Premium** licence to enable access to the Microsoft 365 applications and services required for the user's role. I then verified that the account had been successfully created and appeared within **Active Users**.

---

## Navigation

```text
Microsoft 365 Admin Center
↳ Users
   ↳ Active users
      ↳ Add a user
```

---

## Outcome

I successfully created a new **Microsoft 365** user account, assigned a **Microsoft 365 Business Premium** licence, and verified that the account appeared within **Active Users**. This demonstrates a common onboarding task performed by **IT Support** and **Help Desk** technicians when provisioning new employees.

# Task 2 - Manage Microsoft 365 Administrator Roles

## Objective

Assign an appropriate **Microsoft 365** administrator role to a user account by following the **principle of least privilege**, ensuring the user receives only the permissions required to perform their role.

---

## Implementation

I accessed the user's account within the **Microsoft 365 Admin Center** and opened the **Manage roles** settings. From there, I enabled **Admin center access** and assigned the **Helpdesk Administrator** role to the user account.

Assigning only the permissions required for the user's responsibilities helps maintain security while allowing authorised administrative tasks to be performed.

---

## Navigation

```text
Microsoft 365 Admin Center
↳ Users
   ↳ Active users
      ↳ Select User
         ↳ Manage roles
```

---

## Outcome

I successfully assigned the **Helpdesk Administrator** role to the user account using the **principle of least privilege**. This demonstrates a common administrative task performed by **IT Support** technicians when granting users the appropriate level of access within **Microsoft 365**.

# Task 3 - Monitor Microsoft 365 Service Health

## Objective

Monitor the **Microsoft 365 Service Health** dashboard and understand how it is used to identify service incidents before troubleshooting individual user issues.

---

## Implementation

I accessed the **Service Health** dashboard within the **Microsoft 365 Admin Center** to review active incidents, advisories, and the current status of Microsoft 365 services.

I also opened the **Report an issue** form and reviewed the information required to report a potential service problem to Microsoft, including the affected service, issue category, business impact, and a brief description of the problem.

Checking **Service Health** is an important first step when multiple users report similar issues, as it helps determine whether the problem is caused by a wider Microsoft service incident rather than an individual device or account.

---

## Navigation

```text
Microsoft 365 Admin Center
↳ Health
   ↳ Service health
      ↳ Report an issue
```

---

## Outcome

I successfully reviewed the **Microsoft 365 Service Health** dashboard and identified how active incidents and service advisories are displayed. I also demonstrated how to begin reporting a service issue to Microsoft, providing a practical method for identifying and escalating wider Microsoft 365 service problems.
